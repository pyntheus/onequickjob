# Contract-change requests from L1

See README.md for the format. Items 1 to 3 are changes L1 made to foundation-owned files
(item 1 on Hasan's instruction, items 2 and 3 because the lane's tests couldn't pass
without them); the rest are requests for integration (I).

## 1. Ineligible counters lapse (ruling A9), made in the shared marketplace
- What: `app/services/marketplace.py`: `accept_counter` no longer just refuses when the
  provider behind the counter can no longer take the job (`eligibility.can_take` fails,
  before the transaction or inside it). The refused acceptance still rolls back as before;
  then `_lapse_unavailable` runs a transaction of its own that marks the offer `lapsed`
  (guarded on `pending`), pushes a `counter_lapsed` event on the still-open request (guarded
  on `open`) and texts the provider the new `counter_lapsed` template (shared section of
  `app/services/templates.py`; idempotency key `offer:<id>:counter_lapsed`), with the
  eligibility reasons. The customer gets `409 provider_unavailable` with the message
  "Mike can no longer take this job. We're still finding someone local." (the provider's
  first name). `app/models/job_requests.py` (L1-owned) gains event kinds `counter_lapsed`
  and `expired`. Recorded as A9 in decisions.md.
- Why: Hasan's ruling, given in the L1 brief. L2 builds on it (a lapsed counter on the
  provider's job list, the `counter_lapsed` text).
- Tests: `tests/shared/test_marketplace.py`:
  `test_a_suspended_providers_counter_cannot_be_accepted` (extended),
  `test_a_counter_lapses_when_documents_run_out_inside_the_acceptance` (new),
  `test_a_suspension_during_the_transaction_is_seen_by_its_retry` (the counter case now
  ends `lapsed`); `tests/customer/test_requests.py`:
  `test_an_ineligible_counter_lapses_and_the_request_stays_open`.
- Breaking? No: same status code and error code; the offer ends `lapsed` instead of staying
  `pending`, and an outbox message and a request event are added.

## 4. Scheduling: long first visits and the four-week fallback (bug)
- What: `app/services/schedule.first_slot`. (a) A first visit longer than its window never
  fits (a first regular clean is 240 minutes; the morning window is 09:00 to 12:00), so
  every day is skipped; (b) the fallback after four weeks then books tomorrow at 09:00
  without checking the provider's working days, the customer's days or time off. In the L1
  walk-through, two weekday-only requests booked with providers who don't work Sundays got
  "Sunday 4 October, morning".
- Suggested fix: let a visit start at the window's start when the day is otherwise free even
  if it runs past the window's end, and make the fallback the first day that passes the
  same working-day, customer-day and time-off checks.
- Workaround now: none in L1 (the booking is created by the shared service).
- Breaking? No. Affects L1 (booking screens) and L2 (Today's round).

## 5. `Messages.mark_read(thread_id, user_id)`
- What: a repo function on `app/repos/messages.py` that adds the user to `read_by` for the
  thread's messages.
- Why: the customer's thread list shows unread counts (`ThreadSummary.unread`); opening a
  thread must clear them.
- Workaround now: `app/customer/threads.py` does the same `update_many` through
  `Messages(db).coll`.
- Breaking? No.

## 6. `schedule.ensure_horizon` from a given day
- What: an optional `from_day` (or a separate `fill_from(series, day)`), so the horizon can
  be rebuilt from the next visit after a plan's frequency changes.
- Why: `ensure_horizon` only adds visits after the plan's latest visit (cancelled ones
  included), so after cancelling the visits that no longer fit it adds nothing in between.
- Workaround now: `app/customer/account._fill` builds the visits the same way (about 20
  lines) and reuses a date's cancelled visit if the new frequency lands on it.
- Breaking? No.

## 11. Lane worktrees: `web/node_modules` is a root-owned mount point
- What: `infra/compose.app.yml` mounts an anonymous volume at `/app/web/node_modules`, so
  Docker creates an empty, root-owned `web/node_modules` in a worktree that has none, and
  host `npm ci` (`make install`, `make lint`, `make test`) then fails with EACCES. L2's and
  L3's worktrees have the same empty directory.
- Workaround now: handed it back once with
  `docker run --rm -v "$PWD/web/node_modules:/nm" alpine chown "$(id -u):$(id -g)" /nm`,
  then `npm ci`.
- Suggested fix: create `web/node_modules` (owned by the user) in `make dev` before Compose
  starts, or document the step in README.
- Breaking? No.

## 12. Make `marketplace._provider_now` public
- What: rename it (say `marketplace.provider_for_booking`) or export it.
- Why: invite acceptance books with `create_booking` outside the marketplace and needs the
  same in-transaction eligibility guard: writing the provider so a suspension or document
  change committing meanwhile conflicts with the booking (A7). L1 calls the private function
  rather than copying it (Codex review).
- Breaking? No.

## 13. The shared Mongo container needs a higher open-file limit (infra)
- What: `infra/compose.shared.yml`, the mongo service: `ulimits: { nofile: { soft: 64000,
  hard: 64000 } }` (Mongo's own start-up warning: "Soft rlimits for open file descriptors
  too low", current 1024, recommended 64000).
- Why: with four worktrees' APIs and the lanes' test suites on the one `oqj-mongo`, it ran
  out of descriptors ("Too many open files", errno 24) and segfaulted at 05:05:59 UTC on
  3 October (restart count 3 by then). Every lane's database drops while it restarts; one of
  L1's full test runs failed a setup with a closed connection because of it (passes on re-run).
- Workaround now: none (F-owned infra, shared by every lane); re-run a test suite that hits it.
- Breaking? No.
