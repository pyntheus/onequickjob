# Ownership: where things live, now the lanes are finished

The build ran as foundations (F), three parallel lanes (L1 customer, L2 provider, L3 admin and
payments), a shared-fixes session (S) and integration (I). All of them are merged. The lane
worktrees, branches and databases are gone, and integration closed the contract-change process:
every request in `contract-changes/` is resolved or deferred, with its reason.

**There are no lane boundaries any more.** One session at a time works in `/srv/oqj/main` on its
own branch and opens a pull request; Hasan merges. Any file may change, but each area below
keeps its job and its rules, so a change lands where the next person will look for it. The
collection owners in `domain.md` (generated by `make docs`) say which area writes what.

## API (`api/`)

| Area | Path | What lives there | Rules it carries |
|---|---|---|---|
| Customer | `app/customer/**` | `/api/c`: quotes into requests, the request page, bookings, plans (A10, A22), visits, ratings, invites, messages, the demo simulator | the web never works out a price or fee: these endpoints return them |
| Provider | `app/provider/**` | `/api/p`: jobs, Today, finishing visits, earnings, the limit, the tax pack, time off and cover, helpers (A17), own customers, sign-up | provider-area copy is large and plain; helpers only ever see their own visits |
| Admin | `app/admin/**` | `/api/admin`: overview, the map (A30 to A35), providers and helpers' checks (A20), pricing versions and calibration, disputes, the catalogue, the HMRC export | one admin can't both draft and approve a pricing version; every action is audit-logged |
| Payments | `app/payments/**`, `app/adapters/payments/**` | charging (`charging.charge_visit`, the one path), refunds, webhooks, the PaymentGateway interface, the fake (the default) and Stripe | never inside a transaction; idempotency keys per visit and attempt |
| Shared logic | `app/services/**` | money-adjacent and cross-area rules: marketplace (atomic first acceptance, counters, cover), bookings and schedule, eligibility, lifecycle (A19, A24), guide raises, ledger, notify and the template catalogue, audit, auth | call these, never copy them; every write takes `session=` |
| Core | `app/core/**` | config, db (`transaction`), money (the only fee maths), rounding, ids, time, phone, crypto, errors, auth dependencies | CLAUDE.md's rules that never bend |
| Data | `app/models/**`, `app/repos/**` | one model and one repository per collection, registered in `app.repos.ALL` | repositories raise domain errors (`Conflict`), never HTTP ones (A18) |
| Shared endpoints | `app/shared/**` | health, config, auth, the demo endpoints, catalogue, quotes, address look-up, the admin outbox, files, the offer endpoints | demo endpoints answer 404 when `DEMO_MODE` is off |
| Pricing | `app/pricing/**` | the ported pricing models and engine | the golden tests never change |
| Seed | `app/seed/**`, `seed/*.json` | the demo data; `make seed` resets the demo (A21) | idempotent: two runs leave the same state |

Tests mirror the areas (`tests/customer`, `tests/provider`, `tests/admin`, `tests/payments`,
`tests/shared`); `tests/conftest.py` and `tests/factories.py` serve them all.

## If sessions run in parallel again

Give each its own worktree (`git worktree add`, then `make env`, and set `API_PORT`,
`WEB_PORT` and `MONGO_DB` in its `.env`; the Makefile keeps containers and test databases
apart by worktree name), split the work by the areas above, and bring back the contract-change
files: a session that needs a change in another's area writes it up in
`docs/spec/contract-changes/<session>.md` instead of making it. The finished requests in that
folder show the format.
